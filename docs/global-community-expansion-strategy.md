# Trazo 커뮤니티·동호회 및 글로벌 확장 전략

> 작성 기준일: 2026-11-09 · 대상 코드베이스: 현재 `trazo` 저장소 · 이 문서는 공개 자료와 현재 코드를 함께 검토한 제품·기술 제안서이며, 법률 자문이나 시장 규모 산정 보고서는 아니다.

## 1. 결론 요약

Trazo의 글로벌 확장은 **가능하지만, 현재 구조에서 국가와 언어만 추가하는 방식으로는 어렵다.** 경로 좌표와 GraphHopper 자체는 세계 좌표계를 처리할 수 있고 GPX·FIT·TCX·KML·GeoJSON이라는 국제 호환 자산도 이미 갖추고 있다. 반면 실제 서비스 계층은 카카오 지도·카카오 장소 검색, 대한민국 OSM 파일, 한국어 UI와 SEO, km·m 단위, Google 전용 로그인에 강하게 결합되어 있다. 따라서 먼저 지도·라우팅·지오코딩을 공급자 인터페이스로 분리하고, 다국어·단위·시간대·사용자 ID·공간 검색을 플랫폼 공통 계층으로 만들어야 한다.

제품 방향은 “또 하나의 Strava”가 아니라 **경로가 실제 모임으로 이어지고, 모임을 거듭할수록 더 신뢰할 수 있는 경로 자산이 쌓이는 Route-to-Club OS**가 적합하다. Trazo의 강점은 활동 기록 피드가 아니라 경로 제작, 세밀한 편집, 고도·경사 분석, 웨이포인트, 다양한 기기 파일 내보내기에 있다. 여기에 동호회, 경로가 연결된 일정, 페이스 그룹, 참가·대기 명단, QR 출석, 경로 버전과 현장 위험 제보를 더하면 국내 대표 서비스와 해외 대형 서비스 모두와 다른 조합을 만들 수 있다.

가장 먼저 만들 기능은 ① 동호회와 역할, ② 경로 스냅샷이 붙은 모임 일정, ③ 페이스 그룹·정원·참가/대기·공지, ④ 기간이 지나면 만료되는 구간 상태 제보, ⑤ 신고·차단·운영 감사 기록이다. 실시간 위치 공유, 자체 활동 기록, 결제, 1:1 메시지는 가치가 있지만 개인정보·안전·운영 복잡도가 매우 커 초기 범위에서는 미루는 것이 좋다.

## 2. 현재 제품이 가진 출발점

현재 Trazo는 이미 다음 자산을 보유한다.

- 자전거·러닝 경로 생성, 순환·왕복, 종목별 경로 옵션, 고도·경사 분석과 예상 시간
- GPX·FIT·TCX·KML·GeoJSON 가져오기/내보내기, 웨이포인트와 코스 이미지
- 비공개·링크 공유·전체 공개, 공개 코스 복사, 좋아요·댓글, 최신·담기·좋아요 정렬
- 공개 코스 지도 탐색과 검색엔진용 코스 페이지, 사용자 폴더, Google 로그인
- AI가 코스를 검색·분석할 수 있는 읽기 전용 MCP

즉 커뮤니티의 최소 구성은 있으나, 현재 객체의 중심은 여전히 `Course` 하나다. 관계도 `CourseLike`, `CourseComment`, `CourseShare`가 코스에 직접 달리는 형태이며, 사람 간 관계, 그룹, 일정, 참가, 알림, 신고, 활동 완료에 해당하는 도메인은 없다. 지금의 커뮤니티는 “공개 코스 갤러리”에 가깝고 “반복적으로 함께 운동하는 동호회”는 아직 모델링되지 않았다.

### 3.2 국내 서비스와의 비교 해석

국내 비교는 공개적으로 확인 가능한 대표 기능을 기준으로 한 방향성 비교이며, 모든 버전·요금제·비공개 실험 기능을 망라한 단정은 아니다. 트랭글은 운동 기록, 코스북·따라가기, 내비게이션, 2만 개 수준의 배지 같은 완주 동기 부여가 강하고([App Store 설명](https://apps.apple.com/kr/app/%ED%8A%B8%EB%9E%AD%EA%B8%80-%EB%93%B1%EC%82%B0-%EC%A7%80%EB%8F%84-%EA%B1%B7%EA%B8%B0-%EB%A7%8C%EB%B3%B4%EA%B8%B0-%EC%9A%B4%EB%8F%99-%EC%9E%90%EC%A0%84%EA%B1%B0/id505902704)), Ramblr는 위치가 붙은 미디어 스토리와 공개 여행 기록에 강하다. 오픈라이더 계열은 자전거 내비게이션과 주행 기록, 런데이 계열은 코칭·훈련 프로그램 성격이 강하다.

따라서 Trazo가 “기록, 배지, 피드, 내비게이션”을 각각 그대로 따라 하면 이미 학습된 경쟁 구도로 들어간다. 반대로 **정교하게 만든 경로 → 동호회 일정 → 페이스별 참가 → 당일 변경 → 출석 → 상태 피드백 → 다음 경로 개선**을 하나의 닫힌 고리로 제공하는 조합은 상대적으로 비어 있다. 이것이 우선 검증할 차별점이다.

### 3.3 사례에서 반복되는 성공 원리

1. 콘텐츠가 아니라 행동 단위가 중심이다. 코스 저장에서 끝나지 않고 “언제, 누구와, 어떤 속도로 갈 것인가”로 이어진다.
2. 공개 피드와 소속 커뮤니티는 역할이 다르다. 공개 영역은 발견, 클럽 영역은 신뢰·반복·운영을 담당한다.
3. 경로는 단순 선이 아니라 버전이 있는 공동 자산이다. 주최자 변경, 위험 구간, 대체 경로가 참가자에게 전달되어야 한다.
4. 경쟁만으로 잔존을 만들지 않는다. 출석, 도움, 안전 제보, 경로 검수 같은 기여도 인정한다.
5. 커뮤니티 기능과 안전·운영 기능을 동시에 만든다. 정원, 역할, 신고, 긴급 정보 접근 권한, 변경 이력이 빠지면 실제 모임 도구가 되기 어렵다.

## 4. 권장 제품 포지셔닝

**한 문장:** “Trazo는 가장 좋은 경로를 함께 만들고, 실제로 함께 달리고, 다음 모임을 더 안전하게 만드는 경로 중심 동호회 플랫폼이다.”

Strava의 핵심인 전 종목 활동 기록 피드를 정면으로 복제하지 않는다. Trazo는 계획 전후를 모두 소유하되, 초기에는 휴대폰 GPS 기록기보다 “모임 전 계획과 모임 후 경로 지식”에 집중한다. Garmin·Wahoo·Strava에서 생성된 활동 파일을 가져올 수 있으므로 기록 원천을 모두 직접 대체할 필요도 없다.

제품의 핵심 루프는 다음과 같다.

`경로 발견/제작 → 클럽 라이브러리에 검수 저장 → 경로 스냅샷으로 일정 생성 → 페이스 그룹별 참가 → 변경·안전 공지 → QR 출석/완료 확인 → 상태·사진·대체 구간 제보 → 경로 새 버전 → 다음 일정`

추천 북극성 지표는 단순 가입자나 공개 코스 수가 아니라 **주간 성공 모임 수(경로가 연결되고 실제 체크인 3명 이상인 일정)**다. 보조 지표로 경로→일정 전환율, 참가 신청→출석률, 4주 재참가율, 모임 후 상태 제보율, 동호회 경로 재사용률, 안전 신고 처리 시간을 본다.

## 5. 신규 기능 제안과 우선순위

### P0: “경로가 붙은 동호회 일정” MVP

#### 5.1 동호회와 역할

- 공개·승인제·초대 전용 동호회, 지역·종목·소개·대표 이미지
- 소유자, 관리자, 경로 관리자, 라이드/런 리더, 안전 담당, 일반 멤버 역할
- 가입 질문, 운영 규칙 동의, 초대 링크와 QR, 가입 승인·탈퇴·강퇴
- 동호회 공지와 일정별 스레드. 1:1 DM은 초기 제외하고 운영 범위를 줄인다.

#### 5.2 경로 스냅샷 기반 일정

- 날짜·시각·IANA 시간대, 집결 장소, 연결 경로, 도로/트레일/혼합 노면, 준비물, 우천 정책
- 일정 생성 시 원본 코스의 불변 스냅샷을 만든다. 원본이 수정되어도 참가자가 받은 코스가 몰래 바뀌지 않으며, 주최자가 새 버전을 채택하면 변경점과 재동의를 보여준다.
- 페이스 그룹별 속도/페이스, 리더, 후미 담당, 정원, “중간 합류/중도 이탈 가능” 지점
- 참가/불참/대기, 게스트 수, 마감 시각, 캘린더 추가, 변경·취소 알림
- 시작점 현장 QR 체크인과 주최자 수동 출석, 노쇼 기록은 공개 벌점이 아니라 운영자에게만 제공

#### 5.3 최소한의 신뢰·안전 계층

- 사용자·댓글·코스·클럽·일정 신고, 사용자 차단, 클럽 내 음소거와 추방, 신고 사유·증거·처리 결과
- 관리자 작업 감사 로그와 콘텐츠 soft delete, 반복 스팸 rate limit
- 긴급 연락처는 선택 입력하고 **해당 일정의 지정 리더가 일정 시간 동안만** 접근하게 한다. 일반 프로필과 분리 암호화하고 조회 로그를 남긴다.
- 이벤트 참가 전에 현장 위험, 보험·면책 범위, 교통법 준수 안내를 명시한다.

### P1: 경로 신뢰 네트워크

#### 5.4 만료되는 구간 상태 제보

일반 댓글과 분리해 `공사/통제`, `노면 불량`, `침수/적설`, `낙석/장애물`, `교통 위험`, `급수·화장실 운영`, `통행 가능`을 경로의 특정 점 또는 구간에 남긴다. 사진, 확인 시각, 예상 종료 시각, 종목, 긍정·부정 확인을 포함하고 기본 만료 시간을 둔다. 오래된 위험 제보가 영구 경고로 남지 않게 “현재성”을 제품 규칙으로 만든다.

#### 5.5 경로 버전·계보와 영향 알림

- 다른 사람의 코스를 복사하면 `source_course_id` 한 단계만 남기는 현재 방식 대신 원본 계보와 버전을 보존한다.
- 두 버전의 거리·상승·변경 구간을 지도에서 비교하고, 위험 제보 때문에 우회한 이유를 변경 기록에 남긴다.
- 해당 코스를 저장했거나 다가오는 일정에서 사용하는 사람에게 “4.2km 지점 통제, 새 버전 검토”처럼 영향 알림을 보낸다.
- 동호회 경로는 초안→검수 중→승인→폐기 상태와 검수자를 가진다.

#### 5.6 지역 하이라이트와 기여 신뢰도

카페·급수·전망·정비소 같은 장소뿐 아니라 “차량이 빠른 300m”, “야간 조명 없음”, “그룹 재집결에 좋은 넓은 공간” 같은 **구간 하이라이트**를 지원한다. 실제 완료 기록이나 동호회 체크인이 있는 사용자의 확인에 더 높은 가중치를 주되, 단순 팔로워 수가 진실을 결정하지 않게 한다. 지역·종목별로 유용한 제보를 꾸준히 한 사용자를 `Local Steward`로 표시한다.

### P2: 반복 참가와 확장

#### 5.7 동호회 경로 지도·컬렉션

- 동호회가 승인한 모든 경로를 한 지도에서 검색하고, 거리·상승·노면·난이도·시작점·계절·초보 적합 여부로 필터링
- “한강 야간 30km”, “서울 첫 업힐”, “부산 출장 러닝” 같은 컬렉션과 다일 코스
- 실제 활동 heatmap이 아니라 초기에는 **동호회가 계획·승인한 경로 heatmap**을 제공해 개인정보 위험을 줄인다.

#### 5.8 경쟁보다 기여를 보상하는 패스포트

거리 순위만 만들지 말고 `신규 멤버 동행`, `후미 담당`, `상태 제보 5회`, `지역 컬렉션 완주`, `서로 다른 클럽 공동 행사 참가` 같은 패스포트와 배지를 제공한다. 속도가 느린 멤버도 공동체의 중요한 구성원이 될 수 있어야 한다.

#### 5.9 공동 주최와 지역 연합

두 개 이상 동호회가 하나의 일정과 참가 정원을 공동 관리하고, 각 클럽의 리더·참가 그룹을 구분한다. 도시·관광기관·대회 주최자가 공식 컬렉션이나 기간 한정 패스포트를 운영할 수 있게 하면 향후 B2B 수익화에도 연결된다.

#### 5.10 모임 후 지도 스토리

참가자가 올린 사진을 경로 위치와 연결하고 주최자가 대표 사진, 하이라이트, 우회 구간을 편집해 하나의 회고 페이지를 만든다. 이는 기록 수치가 아니라 사람과 장소를 중심으로 공유되는 성장 채널이다. 얼굴 공개와 위치 공개는 각각 동의를 받는다.

## 6. 글로벌 확장 가능성: 현재 구조 진단

### 6.1 가능한 기반

- 좌표 검증은 위도 `-90~90`, 경도 `-180~180`을 허용하며 경로 거리 계산도 Haversine 기반이라 데이터 모델의 기본 좌표계는 글로벌 사용이 가능하다.
- GraphHopper는 OSM PBF와 고도 데이터를 읽는 오픈소스 라우팅 엔진이며 국가별 OSM 파일로 교체할 수 있다. [GraphHopper 공식 저장소](https://github.com/graphhopper/graphhopper)
- GPX·FIT·TCX·KML·GeoJSON 및 Garmin 계열 웨이포인트는 해외 사용자와 기기에도 통용된다.
- UTC 기반 `utc_now()`와 Firebase 인증은 지역 확장의 기초로 쓸 수 있다.

OSM “데이터가 무료”인 것과 OSM 재단의 공개 타일 서버를 상업 서비스가 무제한 사용해도 된다는 것은 다르다. 공개 타일은 SLA가 없고 대량 다운로드를 금지하며 공급자를 코드에 고정하지 말라고 권고한다. 따라서 글로벌 지도는 비용·귀속 표시·캐시·장애 전환 정책을 가진 타일 공급 계층으로 설계해야 한다. [OSM Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/)

### 6.3 커뮤니티 규모에서 드러날 현재 백엔드 한계

1. `backend/main.py` 하나에 인증, 코스, 커뮤니티, 관리자, SEO, OAuth, MCP, 공간 분석이 2,400줄 이상 모여 있다. 기능별 모듈과 service/repository 경계를 먼저 나눠야 신규 팀과 독립 배포가 가능하다.
2. 좌표와 선이 JSON 문자열로 저장되어 공간 인덱스를 쓸 수 없다. `/community/map`은 최근 후보 최대 3,000개를 읽어 Python에서 bounds를 계산·필터링하고 최대 300개를 반환하므로 도시·국가가 늘면 정확도와 비용이 급격히 나빠진다.
3. 스키마 변경이 `create_all`과 수동 `ALTER TABLE` 사전에 의존한다. 동호회·이벤트처럼 관계가 많은 도메인 전에 Alembic 같은 버전 마이그레이션과 rollback 절차가 필요하다.
4. `created_at` 등 일부 시간이 timezone 없는 문자열이고, 댓글·좋아요의 FK/삭제 연쇄·인덱스가 모델에서 명확하지 않다. `timestamptz`, 실제 FK, 제약 조건과 복합 인덱스로 정리해야 한다.
5. 커뮤니티 목록은 offset pagination과 각 코스별 상관 count subquery를 사용한다. cursor pagination, 집계 테이블 또는 캐시, 이벤트 기반 count 갱신이 필요하다.
6. 알림·이미지 처리·번역·위험 제보 만료·검색 색인은 요청 경로 밖의 작업 큐로 분리해야 한다. Redis/큐, object storage, CDN, structured log, tracing, SLO를 추가한다.
7. `allow_origins=["*"]`와 공개 API 정책은 웹 origin·rate limit·abuse 방어 기준으로 재검토해야 한다. 인증 헤더를 쓰는 앱, MCP, 공개 읽기 API의 CORS 정책을 분리한다.

### 6.4 권장 데이터 구조

기존 `Course`를 즉시 없애지 말고 다음 구조로 점진 이관한다.

| 핵심 엔터티 | 주요 필드/관계 |
|---|---|
| `User` / `UserIdentity` | 내부 UUID, locale, unit system, timezone, 외부 인증 provider+subject. Firebase UID를 비즈니스 FK로 직접 확산하지 않음 |
| `Club`, `ClubMember`, `ClubRole` | 공개 범위, 지역 geometry, 가입 상태, 세분화된 권한, 규칙 버전과 동의 시각 |
| `Course`, `CourseVersion`, `CourseLineage` | 현재 버전, 원작자, 파생 관계, PostGIS `LineString`, bbox, simplified geometry, 통계, 변경 이유 |
| `ClubCourse` | 클럽별 초안/검수/승인/폐기, 검수자, 태그, 마지막 실제 사용 시각 |
| `Event`, `EventRouteSnapshot`, `PaceGroup` | UTC+IANA timezone, 집결점, 코스 버전 스냅샷, 속도, 리더/후미, 정원, 우천 정책 |
| `RSVP`, `CheckIn`, `Guest` | 참가 상태, 대기 순서, 선택한 페이스 그룹, 체크인 방식·시각. 긴급 정보와 분리 |
| `ConditionReport` | point/segment geometry, 유형, 관측 시각, 만료 시각, 사진, 확인·반박, moderation 상태 |
| `Highlight`, `Collection`, `CollectionItem` | 장소/구간 추천, locale별 본문, 순서와 다일 stage |
| `Report`, `Block`, `ModerationAction`, `AuditLog` | 신고 대상 다형성, 증거, 처리 상태, 결정 사유, 이의 제기와 관리자 감사 |
| `Notification`, `Subscription`, `OutboxEvent` | 대상·채널·locale·읽음, idempotency, 이메일/push 전달 상태 |

PostGIS에는 원본 선, 단순화한 선, bbox를 저장하고 GiST 인덱스를 둔다. 화면 축척에 따라 단순화 geometry 또는 vector tile을 반환하면 전 세계 공개 코스를 브라우저에 한꺼번에 보내지 않고도 지도 탐색을 확장할 수 있다. 경도 ±180°를 넘는 코스는 일반 bbox 비교가 깨질 수 있으므로 antimeridian 테스트를 포함한다.

## 7. 글로벌 제품 운영에서 빠뜨리기 쉬운 항목

### 7.1 콘텐츠 안전과 규제

공개 코스, 댓글, 클럽, 사진을 제공하면 Trazo는 단순 경로 도구가 아니라 사용자 콘텐츠 플랫폼이 된다. 출시 전 최소한 신고 접수, 처리 상태, 삭제·계정 제한 사유 통지, 이의 제기, 반복 위반 정책, 법집행 요청 절차, 투명성 지표를 준비해야 한다. EU에서는 사용자 콘텐츠를 저장·공개하는 호스팅 서비스에 불법 콘텐츠 notice-and-action 체계가 요구될 수 있다. [EDPB의 GDPR·DSA 안내](https://www.edpb.europa.eu/system/files/2025-11/edpb_factsheet_gdpr_dsa_en.pdf)

정확한 위치는 운동 습관, 집·직장, 종교시설·의료시설 방문을 유추할 수 있는 민감한 데이터다. 공개 기본값을 피하고, 출발·도착 숨김 반경, 프로필과 경로의 공개 범위 분리, 원본 파일의 개인 메타데이터 제거, 데이터 다운로드·계정 삭제·보관 기간을 제공해야 한다. Strava의 global heatmap도 공개 활동만 집계하고 시작·종료 숨김 구간과 opt-out 사용자를 제외하며 여러 사용자가 지나기 전에는 heat를 표시하지 않는다. [Strava heatmap 개인정보 처리](https://support.strava.com/en-us/articles/15401880-what-are-the-global-heatmap-and-strava-metro)

### 7.2 번역보다 현지화

- 종목명, 난이도, 노면, 통행 규칙, 주소 순서, 주 시작 요일, 12/24시간제와 DST를 locale별로 다룬다.
- 사용자 작성 콘텐츠 자동 번역은 원문과 번역을 함께 표시하고 신고·안전 공지는 사람 검수 또는 고신뢰 번역 경로를 둔다.
- 국가 이름으로 한 번에 “글로벌” 출시하지 말고 OSM 품질, 경로 회귀 테스트, 현지 운영 파트너, 지원 언어가 준비된 **도시/권역 단위**로 연다.
- 초기 후보지는 기존 사용 데이터에서 해외 GPX 가져오기, 공유 링크 방문, 영어 가이드 유입을 분석해 정한다. 근거 데이터 없이 미국·유럽 전체를 동시에 선택하지 않는다.

### 7.3 AI 차별화 확장

현재 MCP는 좋은 선행 자산이다. 동호회 기능이 생기면 쓰기 권한을 바로 넓히기보다 다음 읽기/초안 도구부터 제공한다.

- “이번 토요일 20명, 초급/중급 두 그룹, 비 예보일 때 대체 가능한 40km 클럽 경로 찾기”
- “다가오는 일정 중 만료되지 않은 위험 제보가 걸리는 경로와 대체 버전 요약”
- “지난 8주 출석과 노쇼를 개인 평가 없이 집계하고 다음 달 정원 추천”
- “해외 참가자를 위해 공지 초안을 영어·일본어로 만들되 게시 전 운영자 승인”

AI가 일정 생성·공지 발송·멤버 관리 같은 외부 효과를 내는 단계에서는 명시적 scope, 미리보기, 승인, idempotency key, 감사 로그가 필요하다.

## 8. 단계별 실행 로드맵

### Phase 0 — 기반 정리와 수요 검증 (4~6주)

- 8~12개 자전거·러닝 동호회 운영자를 인터뷰하고 실제 일정 공지, 참가 집계, 코스 배포, 당일 변경, 안전 사고 흐름을 관찰한다.
- 핵심 가설은 “좋아요가 더 필요하다”가 아니라 “카카오톡·시트·Strava/RWGPS 링크로 흩어진 운영을 경로 중심으로 합치면 반복 사용한다”로 둔다.
- 프론트 문자열 i18n 키 추출, locale/unit/timezone 기본 모델, 내부 사용자 UUID 설계, Alembic 도입, 백엔드 모듈 분리를 시작한다.
- MapAdapter와 Geocoder 인터페이스를 만들되, 이 단계에서 한국 지도 공급자를 교체할 필요는 없다.
- 분석 이벤트와 북극성 지표를 먼저 심는다.

**종료 조건:** 인터뷰 대상 중 최소 5개 클럽이 프로토타입으로 실제 일정을 운영하겠다고 동의하고, 이벤트/RSVP 데이터 모델 및 개인정보 영향 검토가 승인됨.

### Phase 1 — 한국 동호회 MVP (8~12주)

- 동호회, 역할, 가입, 경로 라이브러리, 경로 스냅샷 일정, 페이스 그룹, RSVP·대기, 공지, QR 출석
- 신고·차단·감사 로그, 운영자 도구, 이메일/웹 알림
- 5~10개 디자인 파트너 클럽에 제한 출시하고 기존 단톡방을 완전히 없애려 하지 말고 공유 링크·캘린더·공지 복사를 제공

**종료 조건 예시:** 8주 내 주간 성공 모임 30회, 신청 대비 출석 70% 이상, 참여 클럽의 50% 이상이 4주 연속 사용, 심각 신고의 운영 SLA 충족.

### Phase 2 — 경로 신뢰 기능과 영어 제품 (8~12주)

- 상태 제보와 만료, 코스 버전 비교·영향 알림, 클럽 검수 상태, 지역 Highlight/Steward
- 전체 사용자 화면 `ko`/`en`, metric/imperial, timezone, Unicode handle, locale SEO
- PostGIS 이관, 공간 인덱스, cursor pagination, simplified geometry API
- Google 외 로그인 수요를 확인해 Apple·이메일 링크 중 우선순위 추가

**종료 조건:** 위험 제보의 유효 확인률과 처리 시간이 목표를 충족하고, 영어 UI의 핵심 퍼널이 한국어 대비 치명적으로 하락하지 않음.

### Phase 3 — 한 개 해외 권역 베타 (10~16주)

- MapLibre 계열 글로벌 지도, 해당 권역 geocoder, 지역 GraphHopper shard, 국가별 회귀 경로 세트
- 현지 클럽 5개 이상과 공동 베타, 법률·개인정보·콘텐츠 운영 채널, 현지화된 안전 안내
- 권역별 라우팅 SLO, 비용/1,000 route requests, 실패·우회 품질을 계측

**해외 권역 선택 기준:** 이미 유입되는 사용자/파일, 영어 지원만으로 가능한 시장, OSM 자전거·보행 데이터 품질, 현지 클럽 파트너, 지도·지오코딩 비용, 규제·지원 시간대. 이 점수 없이 “시장 크기”만으로 고르지 않는다.

### Phase 4 — 네트워크와 수익화

- 공동 주최, 패스포트, 컬렉션, 클럽 경로 heatmap, 행사 후 스토리
- 클럽 Pro: 고급 역할, 출석/경로 분석, branded page, 대량 초대, export, 공식 컬렉션
- 지역·관광·대회 파트너: 검증된 컬렉션, 기간 한정 패스포트, 스폰서 표시는 광고임을 명확히 구분
- 결제와 실시간 위치는 별도 위험 검토와 네이티브 앱 전략이 성립할 때 진행

## 10. 바로 이어서 결정할 사항

1. “활동 기록 SNS”가 아니라 “경로 중심 동호회 운영”을 1차 포지셔닝으로 채택할지 결정한다.
2. 디자인 파트너로 자전거 클럽과 러닝 크루를 각각 최소 3곳 모집한다. 두 종목의 페이스·안전·집결 방식 차이를 하나의 모델로 억지 통합하지 않는다.
3. Phase 1 범위에서 DM, 결제, 실시간 위치, 자체 GPS 기록을 명시적으로 제외한다.
4. 글로벌 1차 후보 권역은 제품 감이 아니라 현재 GA·서버 로그·해외 공유 링크·가져온 파일 좌표 분포로 2~3곳을 추린다.
5. 구현 전 `Club → Event → EventRouteSnapshot → PaceGroup → RSVP/CheckIn` 도메인과 권한표, 신고·긴급정보 접근표를 별도 기술 명세로 확정한다.

이 순서라면 한국에서 동호회 제품 가설을 낮은 인프라 위험으로 검증하면서도, 같은 개발이 글로벌 확장에 필요한 사용자·시간대·공간 데이터 기반을 함께 만든다. 반대로 지도부터 전 세계로 넓히고 커뮤니티 가설을 나중에 검증하면 라우팅·타일 비용만 먼저 늘고 Trazo를 계속 써야 할 이유는 약하게 남을 가능성이 크다.
