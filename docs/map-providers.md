# 지도 선택과 API 키 설정

코스 생성 화면의 레이어 버튼은 카카오 일반·위성, OpenStreetMap, 구글 일반·위성 지도를 선택하는 메뉴다. 공유 코스 지도와 코스 탐색 화면에도 같은 메뉴가 있고 선택은 브라우저에 기억된다. 지도 종류를 바꿔도 편집 중인 마커·경로·웨이포인트는 유지된다. 구글 키를 설정하지 않으면 구글 항목은 메뉴에 노출하지 않는다. 이전에 구글 지도를 선택했던 브라우저도 키가 없으면 카카오 지도로 돌아간다.

## 환경 변수

Docker Compose를 사용한다면 저장소 루트 `.env`에 아래 값을 추가한다. `frontend`에서 Vite를 직접 실행한다면 `frontend/.env.local`에 같은 값을 추가한다. 두 위치 모두 예제 파일에 항목이 있다. `VITE_` 값은 빌드된 브라우저 코드에 포함되는 공개 설정이며 서버용 비밀 키를 넣으면 안 된다.

```dotenv
VITE_GOOGLE_MAPS_API_KEY=발급받은_브라우저용_키
VITE_OSM_TILE_URL=https://tile.openstreetmap.org/{z}/{x}/{y}.png
VITE_OSM_ATTRIBUTION=© OpenStreetMap contributors
```

키를 추가하거나 바꾸면 프런트엔드를 다시 빌드해야 한다. 운영 배포 절차는 기존 `./deploy.sh live`를 따른다. 개발용 Compose는 `./deploy.sh dev`로 다시 실행하고, Vite를 직접 실행하는 경우 개발 서버를 다시 시작한다. 이번 변경은 소스 수정이며 운영 서버에 자동 배포하지 않았다.

## 구글 지도

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 선택하거나 만든다. 운영 사용에는 결제 계정 연결이 필요하다.
2. **API 및 서비스 → 라이브러리 → Maps JavaScript API → 사용**을 선택한다. 지도 표시에는 Routes API나 Places API를 추가로 켤 필요가 없다.
3. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → API 키**에서 브라우저용 키를 발급한다.
4. 키의 애플리케이션 제한은 **웹사이트(HTTP 리퍼러)**로 설정한다. 운영은 `https://trazo.runvia.app/*`, 로컬 테스트가 필요하면 `http://localhost:5173/*`, `http://127.0.0.1:5173/*` 등 실제 사용하는 개발 주소만 추가한다. 개발과 운영 키를 분리해도 된다.
5. API 제한은 **Maps JavaScript API**로 제한하고 저장한 키를 `VITE_GOOGLE_MAPS_API_KEY`에 넣는다. 키 문자열을 Git에 커밋하지 않는다.
6. Google Cloud의 사용량·할당량과 결제 예산 알림을 설정한다. 예산 알림 자체는 과금을 강제로 막는 상한이 아니다. 지도 로드는 Google Maps Platform의 과금 조건을 따른다.

정식 JavaScript SDK로 구글 지도를 그리며 비공식 구글 타일 URL은 사용하지 않는다. 인증 실패·네트워크 실패 시 다른 지도를 선택할 수 있다. 실제 키가 없는 개발 환경에서는 구글의 실지도 로딩과 과금 설정까지 검증할 수 없으며 운영 도메인에서 키 제한을 함께 확인해야 한다.

공식 안내: [키 발급 및 API 활성화](https://developers.google.com/maps/documentation/javascript/get-api-key), [사용량과 결제](https://developers.google.com/maps/documentation/javascript/usage-and-billing).

## OpenStreetMap

기본 URL은 API 키 없이 사용할 수 있다. 브라우저에서 HTTPS로 요청하며 지도에 출처를 표시한다. 공개 OSM 타일은 제한 없는 상용 CDN이나 SLA를 제공하는 서비스가 아니다. 트래픽이 커지면 운영 용량과 이미지 이용 조건이 맞는 OSM 타일 공급자를 선택하고 `VITE_OSM_TILE_URL`을 해당 공급자의 XYZ URL로 바꾼다. 공급자가 키를 요구하면 그 공급자의 콘솔에서 **브라우저 공개용 키**를 발급하고 허용 도메인을 제한한다. 서버 전용 키를 URL에 넣으면 안 된다. 추가 출처 표시는 `VITE_OSM_ATTRIBUTION`에 일반 텍스트로 함께 적는다.

OSM 타일은 브라우저의 정상 HTTP 캐시를 사용한다. 일괄 다운로드·오프라인 미리 받기를 구현하지 않으며 공급자의 출처는 지도 영역 안에 유지한다. 공식 정책: [OSM Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/).

## 지원 범위

- 지도 화면은 세 공급자에서 같은 코스 데이터와 편집 기능을 사용한다. 공급자별 확대 단계는 공통 인터페이스에서 변환한다.
- 지도 종류 선택은 **배경 지도 표시**를 바꾸는 기능이다. 해외 길찾기 데이터·외부 라우팅 API를 추가하는 기능은 아니다. 현재 GraphHopper는 계속 한국 데이터를 사용한다.
- 장소 검색은 기존 카카오 검색을 사용한다. 해외 장소 검색 공급자를 이번 변경에서 추가하지 않았다.
- 인쇄용 PNG 이미지 저장은 기존 카카오 렌더러를 유지하고 선택지에 `카카오 일반 지도`, `카카오 위성 지도`라고 표시한다. 구글 지도를 임의로 캡처하거나 OSM 타일을 대량으로 내려받지 않는다. 해외 이미지 저장은 별도의 정식 Static Maps API와 이용 조건을 검토해 추가할 수 있다.

## 경로 수정 적용

백엔드가 모든 러닝·자전거 요청에 페리 통행 금지를 보낸다. 러닝은 산책로 선호를 1.4→1.05배, 큰 차도 회피를 0.7→0.95배로 완화하고 거리 가중치를 1000으로 요청해 과도한 우회를 줄인다. 요청별 custom model을 사용하므로 이 수정에 GraphHopper 그래프 재생성은 필요하지 않다.

저장된 코스의 선은 자동으로 바꾸지 않는다. 코스를 편집 화면에서 열고 `전체 경로 다시 찾기`를 누르면 현재 옵션으로 전 구간을 다시 계산한다. 중간 실패 시 기존 코스를 유지하며, 성공한 변경은 되돌리기로 복원할 수 있다. 이 작업은 직선 연결 구간도 도로를 따라 다시 계산한다. 저장 버튼을 눌러야 저장된 코스에 반영된다.

2026-11-12 운영 GraphHopper에 새 요청 규칙만 보내 검증한 결과:

| 코스 | 구간 | 수정 전 기본 | 수정 후 |
| --- | --- | ---: | ---: |
| 170 이상하게 돌아감 | 2→3 | 1,666.4m | 1,501.9m |
| 171 한강버스 | 2→3 | 10,499.3m, 페리 포함 | 10,265.1m, 페리 없음 |
| 172 횡단보도 | 전체 | 1,115.0m | 1,089.3m |
| 173 횡단보도 2 | 2→3 | 현재 엔진 478.3m; 저장된 선 약 503m | 478.3m |
| 174 서초역사거리 | 2→3 | 226.2m | 200.7m |

173은 현재 엔진에서 이미 저장 당시와 다른 선을 반환한다. 도로 중심선·보도 혼용과 끊긴 보도 데이터는 그대로여서, 실제로 존재하지 않는 길을 만들어 연결하는 식으로 보정하지 않았다. 이 사례를 포함해 현장의 정확한 보행 동선까지 보장하려면 OSM 보도 연결 확인과 지도 데이터 보정이 별도로 필요하다. OSM 배경을 선택하면 길찾기 엔진과 같은 데이터 계열의 도로 구조를 비교하기 쉬워진다.
